## Phase 6 implementation checkpoint

Jobs, job runs, daily items and nightly windows are versioned hub documents. Owner HTTP and external MCP operations create, edit, list and run them. The external Projects job tools use the prefix `jevellan_project_job`/`jevellan_project_jobs`, preserving ordinary conversation job tools. The coordinator lists definitions and receipts and runs enabled jobs; only the owner edits definitions. Jobs consume no model or thread slot and run one at a time on the assigned coordinator device; apps-only devices remain refused.

Command runs snapshot the job and setup command, fetch a private base ref, create a fresh detached worktree and use an isolated minimal environment. Bounded redacted output produces an 8,000-character tail. Registered checkout HEAD, branch, index, tracking ref and status are unchanged, including dirty files. Local versioned process sidecars permit confirmed orphan termination before cleanup after restart. Interrupted command or uncertain dispatch effects are failed without replay; an explicit owner rerun creates a new task. Workflow watchers resume the actual stored run ID and poll at sixty seconds.

Workflow dispatch uses GitHub API version 2026-03-10 with return_run_details, so the response identifies the actual run. A gated dispatch creates a dedicated jv/jobs ref pinned to the earlier passing commit, because dispatch accepts a branch or tag. The receipt checks the actual run's commit. Explicit required job/step names prevent a successful scheduler with skipped tests from passing. Failed logs are redacted; absent permission is reported. No production deployment is configured here.

A window stores its closing project day and complete task plans before creating tasks, repairing missing writes after restart. It serializes only its daily tasks and holds owner API/MCP merges with the prescribed sentence. Completion or the six-hour deadline releases the hold; unstarted window tasks become cancelled, and the persisted outcome notification retries by a stable ID. A session in review counts as an ended daily turn, allowing the hold to close while its pull request awaits the owner. This avoids requiring a merge while merges are held. Window IDs are derived from project/date rather than colon-separated keys to satisfy the existing hub ID contract.

The UI provides job/daily editors, Run now, enable switches, project-day results, receipt logs, workflow links, the project-wide hold banner and a dismissible last-window count.
