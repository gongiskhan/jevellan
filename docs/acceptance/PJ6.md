## Limits

- Everything above is simulated: both devices run on this one machine against one local bare origin, and there is no live Jev answer, no live Claude or Codex turn and no real remote. PJ-live (phase 8) runs the live journey or records it as blocked.
- The vision checks were not run at the phase gate, so no screenshot had a vision judgment then, and no screenshot shows a main thread. Update (2026-10-06): the Projects screenshots, including the Main option in Project settings, were later judged live on dev-madrid at `49106b7` and again at the final commit `6647f91` (104 of 104 ok each time, 0 blocking findings; see REPORT.md). The builder review is a single pass by the builder, not the vision checks brief section 13 asks for.
- The two PJ6 publications run one after the other; the busy lease is proven by the main publication test with one device.
- A checkout claim that cannot be settled (the hub unreachable at release, a stop on a branch the agent switched to, an unconfirmed process exit) stays held and nothing retries it, so that checkout stays refused until it is released by hand (decision 528).
- When the coordinator runs on another device, a restart of a main thread onto main on the same device is refused (decision 529).
- A main thread reads `done` a moment before its claim and reservations are released, so a start or a conversation in that moment is still refused with its title.
- While the hub is unreachable, placement sees only this device's main threads and starts in flight; preparation's claim then refuses a busy checkout by failing that thread. The hub matches a member's claim by its stored path or by the project's thread and conversation indexes, never by resolving member paths.
- The agent's own `git fetch` and `git rebase` after the conflict prompt run with its account environment; that is proven only against the test's local origin, not against an HTTPS remote with a credential helper.
- Reservation paths are compared as given, without normalizing `./` or case (brief 5.11 names no normalization), and a thread created within seconds after mail to all can miss it when its device's clock runs ahead of the hub's.
