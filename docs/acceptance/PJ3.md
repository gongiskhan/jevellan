# PJ3 - the Projects interface

**Evidence label: simulated.** Projects phase 3 (BRIEF-projects.md section 13, local and untracked like BRIEF.md) passes PJ3 as seven Playwright browser journeys in four layouts (desktop and phone, light and dark) on 2026-10-04 (goncalos-macbook-pro). **The automated vision checks were not run**: `JEVELLAN_TEST_CLAUDE_TOKEN` is not set, so every PJ3 vision record says `not run`, and brief section 13's "all screenshots free of blocking findings" is not shown by a vision check. A builder visual review of the screenshots (below) found and fixed problems but does not stand for the vision checks. No part of this evidence is live, and Gonçalo's acceptance is not claimed.

- **Real:** the browser (Playwright's Chromium) driving the compiled web application; the `scripts/test-server.mjs --projects` fixture server's hub and member daemons with their HTTP routes, browser sessions, the coordinator chat SSE stream, the bridge and the hub's SQLite project store; Git (the fixture project's checkout, thread worktrees and `jv/` branches, pushes to a bare origin behind a GitHub-shaped remote redirected with `insteadOf`); process groups.
- **Simulated:** coordinator and thread turns, through FakeRuntime scripted turns that call the daemon's real bridge (decisions 460 and 466); GitHub, through the local fake server `tests/fixtures/github-server.mjs`, whose checks, mergeability and merge the journeys change through the fixture's control routes (decision 462); the two accounts (`Projects Claude`, `Projects Codex`) and their discovered models; the offline device and the member-owned concluded thread (decision 459); the GitHub token is a random fixture value. Since Projects phase 4 the fixture also saves a Jev key, and its fake Jev answers every thread placement, which records `jev` (decision 484).
- **Not run:** the vision checks (ENV-CLAUDE), live Claude and Codex turns and live GitHub (PJ-live, phase 8). The tablet widths (761 to 1180 px) are not in the spec; they were checked by hand in the builder review. Features of later phases are listed under Limits.

Test names and code comments cite the build design's decision ids; [REPORT.md](REPORT.md) lists them under the same ids (for example D54 is decision 430, D56 is 432, D79 is 434, D84 is 436, D91 is 296, D224 is 448 and D245 is 469).

## Builder visual review (not a vision check)

Because the vision checks could not run, the builder reviewed the interface in one round. It opened all 68 PJ3 screenshots of its own spec runs and compared them with the conversation and Settings evidence, then drove a fixture server by hand for states the spec does not capture: every thread state's dot, stopped, in-review and turn-limit thread pages, the Stop confirmation, `Projects offline` (Offline chip, notice and the disabled New thread), the project menu, Answered expanded, the collapsed sidebar with its badge, keyboard focus rings, long names, widths of 1000, 1185 and 1280 px, and the existing New conversation, conversation and Settings pages with the new section, in desktop and phone, light and dark.

It recorded 15 findings:

- **Fixed, blocking (1):** a thread title longer than its row let the row's screen-reader state escape the title's clip, so the phone page scrolled sideways (564 px of content in a 390 px viewport) and the desktop side column scrolled horizontally. The spec now uses such a title and its screenshot helper asserts that nothing scrolls sideways (decision 468).
- **Fixed, major (4):** a raw `mcp__jevellan__jevellan_thread_report` tool row above every report card (decision 469); the live bar (`Jump to latest`, the working line, Interrupt) sitting in the composer's fade over chat text; the capped sidebar list not showing the current project, so the phone drawer opened on other projects; hover leftovers in full-page captures that read as a second selected project (the spec now parks the pointer) (decision 468).
- **Fixed, minor (3):** report cards 4 px off the transcript's inset, decision and pull request cards with different padding, and a square focus ring on the Answered summary.
- **Logged, unchanged (6 minor):** inline code is hard to see on dark panels (an app-wide style); phone header icons and tabs are 32 and 30 px tall, like the app's existing controls; the chip and session text sit 4 px apart on phones (a shared header rule); the sidebar dot follows the coordinator, not the threads (decision 438); a stopped thread's chat card reads the coordinator-facing `The owner stopped this thread.`; the device switcher overflows the sidebar at 761 to 1024 px (pre-existing).
- **Not a product problem (1):** sticky elements composited mid-page in hand-made captures of a scrolled page.

The spec passed 28 of 28 in the four layouts before the fixes and in four consecutive runs after them, and the affected screenshots were read again. Earlier spec runs had found five more product problems, fixed before the review (decision 467): a row clock that ticked too slowly for ages in seconds, a notebook editor that scrolled the page on focus, a sticky inspector that scrolled the page on every keystroke, a sidebar list cut mid-row and a placement line clipped on phones.

## Interface unit tests

`tests/project-work-ui.test.ts` (27 tests) checks the pure interface model and copy that the pages render: `project routes accept only valid project and thread ids and drive the header flag`; `the default tab is Waiting only while a question is open`; `sections: Running holds every live, resting or waiting thread newest first; Concluded the last 14 days by end`; `the page clock ticks every second only while a Running row reads its age in seconds`; `dots follow D54 and the sidebar dot pulses only for a working coordinator`; `sidebar rows sort by name without regard to case`; `coordinator chip labels`; `the header chip follows the chat stream and shows the session, else the planned one, with runtime display names (D91)`; `concluded outcomes: merged, published to main, no changes, stopped and failed`; `pull request badges and the merge block`; `the Pull requests section keeps open pull requests and pushed branches; merged and closed ones are concluded (D58, D222)`; `placement gates disable Main and other devices with the sentences placement refuses with (D88, D221)`; `request bodies: Automatic placement fields are omitted and a stored main default survives a save (D205, D223)`; `decision cards: the source line, where an answer went and how long the sent line stays (D224)`; `every coordinator tool has its own one-liner icon`; `row meta and the placement line use the runtime display name, the branch and the device`; `chat items: owner messages, replies, one-liners, event cards and notices in ledger order, delivered by event id (D2a)`; `working: the view decides when running, unavailable or offline; otherwise an unclosed coordinator turn`; `report cards follow their turn, anchored on the report call and counted from the end (D56)`; `the thread page leaves out completed report calls whose report it shows, after aligning on them (D245)`; `the thread page polls every 1.5 s while live work runs or just after an action, else every 10 s (D79, D230)`; `thread header buttons: Stop until concluded, Discard as the server allows, Allow 10 more turns only at the limit of a live thread`; `the thread composer: the live line, and why it takes no message when attached or concluded (D81)`; `thread transcript notes, report badges and the header pull request badges`; `withdrawn questions need a successful call with its reason, once per ledger id and never for history (D84, D200)`; `time helpers`; `interface copy: brief-verbatim texts, shared server texts and no conversation vocabulary`. The copy test asserts the brief's verbatim interface strings and that the interface's copies of server sentences (placement refusals, `This thread has ended. Start a new thread for new work.`, `Worktree discarded.`) equal the server's.

Phase 3 also adds one server regression test, `project hub reads are admitted outside the lifecycle gate and writes are refused while an installer holds maintenance (D247)` in `tests/project-hub-store.test.ts` (9 tests), for decision 471, and extends the work view schema test fixture in `tests/project-schemas.test.ts` with the placement gates (decision 445).

## Commands and counts

Node 22.22.0 and Homebrew Git 2.55.0 first on `PATH` (Apple Git 2.39 lacks `merge-tree --merge-base`, which the fixture server's preflight needs). Tests import `dist/`, so build first.

```sh
npm run build
npx vitest run tests/project-work-ui.test.ts
npx playwright test tests/e2e/projects.spec.ts --project=desktop-light-projects --project=phone-light-projects --project=desktop-dark-projects --project=phone-dark-projects
```

Results: the interface unit tests passed **27 of 27** in both complete backend runs. The PJ3 spec alone in the four `-projects` layouts passed **28 of 28 in each of its last seven runs** during the build (about 2 minutes each, four workers, all twelve web servers booting each run). The complete phase verification (`npm run build`, `npm run typecheck`, `npm run lint`, `npm test`, `npx playwright test`, `node scripts/secret-scan.mjs --worktree`, `git diff --check`) gave: backend **1464 passed, 4 skipped (live Jev tests without `JEVELLAN_TEST_JEV_KEY`), 0 failed in 115 files (1437 s)**, then after the two gate fixes **1465 passed, 4 skipped, 0 failed in 115 files (1480 s)**; complete browser matrix of 192 cases with four workers **186 passed, 6 failed (40.2 minutes)** and then **172 passed, 20 failed (42.1 minutes)**, with PJ3 **28 of 28** in both. Every failure was an existing `skeleton.spec.ts` journey that timed out waiting on server work under external machine load (one was a kept-alive connection reset); each passed in one-worker reruns in the time it takes at the previous commit, and `skeleton.spec.ts` alone passed **108 of 108**. ## Limits

- Everything above is simulated: no live Claude or Codex turn, no real GitHub repository or pull request, no second device. PJ-live (phase 8) runs the live journey or records it as blocked.
- The vision checks were not run, so no screenshot has a vision judgment. The builder review is a single pass by the builder, not the vision checks brief section 13 asks for.
- No single four-worker browser matrix run was green on this machine; every spec passed, `skeleton.spec.ts` only when run alone. Update for Projects phase 8 (2026-10-06): the phase 8 four-worker matrix passed 208 of 208 on its first run, after the heaviest skeleton journeys got measured budgets (decision 560 in [REPORT.md](REPORT.md)).
- Not in phase 3: Why, Override and the `Placed without Jev` chip (built in phase 4, see [PJ4](PJ4.md)); opening the seeded remote thread, remote thread pages and Move coordinator here (phase 5; the seeded row answers `Remote threads arrive in phase 5.`); the take-over line (phase 7). Update for Projects phase 5 (2026-10-05): remote thread pages and Move coordinator here are built (see [PJ5](PJ5.md)), and the seeded concluded member row now opens `This thread was not found.`, because the fixture writes only its index row. Update for Projects phase 7 (2026-10-05): the take-over line is built (see [PJ7](PJ7.md)).
- The tablet widths (761 to 1180 px) are covered only by the builder's hand checks. After Stop on the thread page the focus falls to the page body, and a failed token read leaves the card on `Loading…` with the app's error toast.
- A fixture server sometimes fails its close on SIGTERM and leaves a small temporary root; the cause is not identified. Update for Projects phase 5 (2026-10-05): a cause that fits these failures was found and fixed (decision 510 in [REPORT.md](REPORT.md)). Update for Projects phase 8 (2026-10-06): the remaining cause, Playwright's process-group SIGTERM reaching the fixture server's own child processes, was found and fixed (decision 559).
