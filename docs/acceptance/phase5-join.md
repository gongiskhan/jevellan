# Phase 5 — Installing a member device

Status: joining is implemented; component, browser and fresh packed two-daemon checks passed. The completed phase-5 browser and installation results are consolidated in [J9](J9.md).

Both `install --join hubUrl code` and `join hubUrl code` prepare the independent installed application and register the member before its service starts. Development checks can supply `--from` with either form. Installer admission excludes running work and stops only its recorded service. The existing mesh join implementation owns registration, private authentication files and the final device record; the CLI does not copy account logins or create a member-local hub database.

The pending service switch records the intended hub without the invitation code. The mesh join plan retains the request/device identity and address. A lost reply can retry the same registration; an already saved device token can complete startup without another invitation. Repeating a completed join preserves its identity and does not restart a healthy service. The command can resume an already prepared version without rebuilding or downloading it. A plain install cannot turn an unfinished join into a hub, and joining cannot convert an existing hub. Data-retaining uninstall preserves membership for reinstall.

Settings now shows `npx github:gongiskhan/jevellan join ...`. Section 4.3 requires installation from the public Git repository and excludes npm publication without authorization; that takes precedence over section 14's older `npx jevellan@latest` example. GitHub fetching remains blocked by the existing publication/authentication limit, so the verified commands use local packed archives.
