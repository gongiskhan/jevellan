## Verification and limitations

- The final targeted browser run passed **four journeys in 48.6 seconds** at 1440×900 and 390×844, light and dark. Typecheck and lint passed. The production build had passed before these fixture/assertion-only changes; no product implementation changed for this journey.
- The initial device Settings regression selection passed four cases while J8 was still being developed. Earlier J8 attempts failed on test issues: native-option disabled matching, an obsolete stream selector, checking terminal status before cleanup finished, and an activity locator matching both the header and Settings. The final checks target the actual visible stream/Settings content and wait for the completed interruption. Failed attempts are not counted as passes.
- Desktop-dark remote correction and phone-light guard captures were visually inspected. Content and controls are readable; the phone page scrolls. The repeated outside-work notice is cosmetic. This inspection does not substitute for the credential-blocked Claude vision check.
- Repository-history/worktree secret scanning and whitespace checks passed. BRIEF.md remains ignored. The existing commit-approval and GitHub-authentication blockers were not retried.
- No second machine, native agent home, installed service or Tailscale configuration was changed. This is targeted journey evidence, not a clean full expanded suite or user acceptance. J11 across devices, remaining Settings mutation recovery, installation and the improver still need work.

Implementation: `tests/e2e/skeleton.spec.ts` and `scripts/test-server.mjs`. The existing private progress preview remains a fixed report with the earlier real Codex demonstration; it was checked reachable with HTTP 200 during this checkpoint and was not replaced.
