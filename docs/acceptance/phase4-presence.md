# Device presence and outside activity

**Live:** local HTTP, SQLite, Git, owned child processes, read-only fixture database access and installed Chrome. **Simulated:** provider responses, outside-agent journals, native-home fixtures and the second device. Hub and member applications have separate homes and listeners in one test process. **Not run:** a live second machine, successful Jev classification, Claude execution/vision or complete J8/J11.

Devices report immediately after recovery and every thirty seconds. Heartbeats include running conversations, registered local checkout state, external session metadata and CPU/free-memory observations. Git reads disable optional index writes, hooks and fsmonitor and never fetch; ahead/behind describe the locally known upstream. Failed delivery is contained, overlapping pulses coalesce, and shutdown drains the current pulse before closing its dependencies.

The sensor reads bounded metadata from Claude Code, Codex, Cursor and Gemini. It excludes sources under Jevellan's isolated runtime homes, including aliases, without hiding an unrelated native session in the same checkout. Paths are canonicalized and mapped to the most specific registered project. Heartbeats contain runtime, cwd, source and last activity, plus a project identifier when known; no transcript text, titles or native session identifiers are returned.

Codex identity comes only from the first metadata record. Discovery includes recently resumed journals in old date directories, skips subagents and deduplicates overlapping roots. Claude journals work without registry entries; registry entries additionally require matching filename/PID, a live process and plausible start time. Cursor metadata reads do not infer cwd from lossy directory names. Its SQLite query runs read-only in a bounded worker and extracts only selected metadata fields. Gemini uses its project mapping and chat header without calling a CLI. Failed sources retain cached rows at their original age and report unavailability; recovered empty results clear them. Stale and future activity cannot become fresh through caching.

A recent outside writer blocks a new writing step before launch. The conversation records the exact blocked manual choice and exposes Retry across reload; a successful retry starts it once. Automatic retries request a fresh decision. During a running step, newly observed outside activity leaves the owned process running and records a durable block against automatic checkpointing and publication. The final boundary samples again for short steps. Under main policy, Changes shows the uncommitted files and Continue accepts only the reviewed fingerprint. Restart retains that requirement. Ordinary publication also checks external activity around its coordination boundary before pushing.
