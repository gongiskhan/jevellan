# Memory and publication during hub outages

**Live:** local HTTP, Git, SQLite, Basic Memory, isolated homes and owned test processes. **Simulated:** provider behavior, additional devices, hub outages and lost replies. This checkpoint does not claim a real second machine or successful live Jev classification.

Queued memory now waits at its ownership checks and checkpoint boundary. The same in-process queue continues after the hub returns, keeping its already-written note references and producing one final memory receipt. It does not replay a write or launch another native step. Waiting checkpoints and memory writes compare the original files and Git snapshot before proceeding. Outside edits remain intact behind the Changes review barrier.

Publication admission and authority checks at settled Git boundaries wait for fresh authority and retain existing verification and rewrite receipts. A lost acquisition reply can recover the same still-valid lease for the same authenticated device and work. A failed lease assertion or renewal ends that lease attempt: recovery settles its exact token and acquires new authority before another attempt. The original renewal error remains typed, so a disconnected hub can be distinguished from a lost or rejected lease without matching error text. Interruption inside an unfinished rebase remains separate work below.

Release is separate from publication. If the push succeeded and its lease-release reply was lost, recovery retries only release; it does not push again. Releasing the same exact token is idempotent and can clear its expired claim, but cannot clear a newer lease or another owner. Checkout release after closing work similarly waits using the completed work's identity. It preserves one closed result without reopening work or scheduling another step.

The common publication path also covers publication reached from context completion, settlement and published undo. Their earlier preparation and mutation boundaries still need their own continuation handling. Restart continues to interrupt waits rather than recreate their in-process continuations.

It includes the previous conversation-wait/routing coverage, later outside edits during memory capture, replacement of a failed publication lease, idempotent/expired cleanup, refusal of stale tokens and waits for already-closed work. The renewal regression still prevents any push after a failed renewal and now verifies that its original typed failure is preserved.

It covers queued-memory checkpoints and undo, outside activity during partial memory capture, ordinary and automatic publication, context creation/merge completion, settlement, published undo, stale verification and cancellation. These test normal conflict integration, but do not prove continuation through an outage inside an unfinished rebase.

The first four assertions mistakenly counted the daemon's `daemon.db` as a checkout claim. Restricting that check to claim documents corrected the fixture; all **four strengthened cases passed in 27.12 seconds**. No product change was needed after the 100- and 15-case runs.
- Final typecheck, lint and the production build passed.
- The subsequent browser run passed **16 workflows in 1.9 minutes** across desktop/phone and light/dark layouts: planned work with verified Changes, correction/redo, reviewed file acceptance and context draft/apply completion. Providers in these browser fixtures are simulated; required Claude SDK vision remains credential-blocked.
