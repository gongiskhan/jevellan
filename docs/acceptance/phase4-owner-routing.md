# Conversation owner routing

**Live:** local HTTP, Git, SQLite, signed sessions, isolated homes and owned test processes. **Simulated:** provider behavior, network failures and extra devices. The daemon applications run on one machine. This does not claim a real second-machine journey, successful Jev classification or complete J8/J11 acceptance.

The shared conversation list now opens foreign conversations through their owner's registered URL. The same explicit route table handles local and relayed history, streaming, recorded files, Changes and conversation controls. New conversations still start on the device whose UI is open. The receiver serves only its local history; it cannot start another proxy hop or move the work into the viewer's home.

Normal UI cookies remain device-bound. The source daemon forwards its authenticated source session in dedicated peer-request headers. The owner asks the hub to verify that source session, both device memberships and the indexed conversation owner. A member makes this check through its own bearer-authenticated hub connection; a hub owner checks locally. The peer endpoint refuses browser-origin requests. It neither sets a browser cookie nor treats another device's cookie as a local sign-in.

An already admitted stream can keep reading during a hub transport outage while the source signature remains valid and unexpired. New requests still require the hub. On recovery, sign-out or device revocation closes the stream. Versioned peer-session input/result schemas carry that check without copying credentials into ordinary data or storing a new session cache.

Forwarding preserves status, query, JSON request contents, response bytes and Last-Event-ID. SSE flows with backpressure and a connect-only deadline; a quiet stream is not ended by that deadline after its headers arrive. Closing the viewer aborts the upstream request and releases its reader, listeners and timer. Ordinary requests retain a deadline through the body. Redirects are refused and Set-Cookie is not relayed. Response bodies stream without collecting the complete conversation in memory. A failure before response bytes remains a structured error; a broken body after transmission starts closes the response so the client can detect the interruption.
