# Periodic settings synchronization and network listeners

**Live:** local hub/member HTTP, installed APM processing local fixture packages, filesystem isolation, loopback and this machine's actual Tailscale IPv4 listener, and Chrome. **Simulated:** provider authorization, secondary device hardware, outside activity, hub loss and the secondary-bind failure. This does not prove access from a second physical machine or successful live Jev classification.

Each daemon now checks shared configuration and Rigging at startup and every thirty seconds. It writes the current configuration to its isolated `apm.yml` and uses the existing runtime delivery path for each account. That path fingerprints its inputs and verifies owned files, so unchanged packages avoid another APM install while missing files can be restored and locally modified files remain protected. The local versioned synchronization receipt records applied, waiting or failed, with redacted diagnostics. Hub failures and account delivery failures retry on later checks. Periodic and explicit delivery requests share an application queue; overlapping timer ticks coalesce. Shutdown stops new checks and drains admitted delivery before closing account/database services.

Daemon startup now listens on loopback and, when detected, the Tailscale IPv4 address, using one port and the same application. A fresh device advertises its selected reachable address. Startup failure closes only the listeners opened by that attempt. An occupied port remains untouched; selecting the next available port belongs to the unfinished installer. The development CLI reports the listening addresses and closes its daemon on interrupt or termination. No installed daemon or existing preview service was restarted or reconfigured.
