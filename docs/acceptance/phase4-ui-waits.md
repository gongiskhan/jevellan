# Hub recovery for UI requests

**Live:** local HTTP, SQLite, Git, isolated homes and Chrome. **Simulated:** provider responses, additional devices and network outages. Successful live Jev classification and Claude vision remain credential-blocked.

The daemon preserves typed hub-unavailable errors and identifies whether the particular request can be repeated. Authentication failure before admission permits a retry; ordinary unavailable responses and post-admission mutations without reconciliation do not. Passphrase sign-in can retry its stateless session issuance. Configuration writes with a request ID and conversation creation with its existing stable IDs have separate repeatable paths. Provider-login polling is excluded from the ordinary GET classification because it can capture credentials and change account state.

Configuration revisions and request receipts commit in one SQLite transaction. Receipts bind the device, request ID and a hash of the validated input to the resulting revision. A retry returns that original revision even after a newer save or a database restart, without replacing newer settings. Changing the body or expected revision under the same ID conflicts. Legacy requests without IDs retain their existing stale-writer rejection. Receipts do not store another copy of the request body or any credential.

The browser explicitly opts supported calls into waiting. It repeats only a typed, retryable hub-unavailable response, retaining the original serialized request in memory. A generic HTTP 503, malformed error, rejected credential or connection loss to the local daemon does not trigger an automatic repeat. The waiting notice uses the specified hub message. Stop waiting, navigation and form unmount abort the pending retry; the notice explains that stopping does not undo a request already received. Pending requests and passphrases are not persisted in browser storage.

Connected callers include workspace authentication/loading, passphrase sign-in, the conversation sidebar and project selector, new conversations, runtime configuration toggles, decisions settings and configuration import application. This is an incremental UI recovery checkpoint, not all Settings mutations or completed section 14.
