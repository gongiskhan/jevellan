# Phase 4: automatic pull request fixes

Status: source and affected functional checks complete; dedicated vision blocked. Nothing installed; the live clock is unstarted.

## Behavior

Checks, conflicts and comments use the existing thread, admission and publication paths. The project must be active, the kind enabled, the thread in review, and the PR below its configured limit. Comments include owners and bots, wait for two quiet minutes, and arrive in batches of at most15 to fit the pending-text bound. No new GitHub comment, reply or review mutation is added.

Attempt ids and notification ids are durable. A round and comment delivery are charged only when the runtime accepts the turn. Disabling queued, unstarted work cancels it without a charge. Internal verification keeps its automatic origin and round. The daemon supplies provenance; the model cannot forge it. Prompt and report labels distinguish automatic work from owner requests.

The owner gets the prescribed limit question. Allow more resumes the same thread; Leave it to me disables automatic work. Owner fix buttons re-enable it without spending a round. Recovered CI withdraws an obsolete question; a later failure can ask again. The coordinator's conflicting older CI instruction is removed.

A navigation regression also exposes the PWA's eight-second fallback leaving a recovered hub on its reconnect page. That public page now checks transport health, with visible-page retries bounded at5–30seconds, immediate checks on visibility/network recovery and one automatic reload when reachable. It never reads or caches an owner document. Try again remains available.
