# Installation commands and work admission

Status: install, update, rollback, data-retaining uninstall and purge have component and packed evidence. Doctor, join, the installed command and optional HTTPS are covered by their follow-up evidence below. The later combined running-conversation, configured diagnostics and guided first-run journeys pass all four layouts; see [J9](J9.md).

The public CLI prepares local checkouts or packed archives, copies an independent application version, installs or reuses private dependencies and registers the exact owned service definition. The update command can fetch the public Git distribution; that remote path has not been run because repository publication remains blocked. Local checkout preparation follows [npm pack](https://docs.npmjs.com/cli/v11/commands/npm-pack/) and [Git prepare](https://docs.npmjs.com/cli/v11/using-npm/scripts/#prepare-and-prepublish) behavior; prepared archives and directories are listed in the install manifest.

`packages/core/src/lifecycle.ts` supplies a SQLite rollback-journal admission lock. A conversation operation holds shared access through preparation, execution and settlement. Mutating HTTP requests, startup recovery and Rigging synchronization also hold admission. The user-invoked installer acquires exclusive access before it stops or switches the recorded service. An exited process releases its lock without a stale timeout. The separate versioned activity snapshot supplies progress text and conversation names; it is not the authority for locking.

The installer records its pending target before stopping the service. A failed stop preserves the old definition. A failed start keeps both versions and the original previous-version reference; retry and explicit rollback are supported. New service startup happens after the exclusive lock is released. Reinstalling the already active, healthy version does not restart it. Dependency repair cannot replace an environment selected by an active application; the error directs a data-retaining uninstall/reinstall instead.

Native daemon ownership is checked when stopping and waiting for startup. A hub's registered address/version is refreshed from its installed device configuration on startup. The Safety command guard covers the added install, join and rollback actions, including ordinary direct Node and npm/npx forms; its documented arbitrary-program limits remain.
