# Joined application execution

**Live:** HTTP listeners, private registration files, SQLite authority, local Git verification/publication and owned child processes. **Simulated:** the second device and provider. The hub and member application instances run in one test process, with separate HTTP listeners and data homes; the scripted runtime uses a real owned child process. **Not run:** a second machine, live Claude execution, successful Jev classification, complete J8/J11 or the remaining phase 4 workflows.

The application now selects its services from the registered device role. A hub creates the authoritative database and local services. A member opens only its private join files and uses authenticated hub interfaces for accounts, configuration, rigging, projects, checkout claims, publication leases and indexes. It keeps runtime homes, memory, context drafts and conversation history locally. A pending or incomplete join cannot silently initialize a new hub. A member refuses a home containing a hub database, and its hub-only device endpoints return 404.

Browser sign-in, account operations, configuration, projects, device rosters, invitations and switch-token exchange now work through either application role. New member requests check the signed session and hub revocation state. Existing SSE connections serialize asynchronous authentication checks, replay without duplicate cursors and retain backpressure. During a network outage, only an already authorized stream may continue with a locally valid, unexpired signature. New requests still fail with hub unavailability, and the stream closes when a subsequent hub check reports revocation.

Rigging delivery receipts now live in the device's own versioned file. Startup saves an existing hub receipt locally before removing the legacy row; conflicting copies are preserved rather than overwritten. Delivery fetches current configuration before preparing accounts. A delayed older configuration response is refetched instead of overwriting a newer materialized manifest. Model discovery also refreshes current hub configuration before materialization, so a delayed discovery response cannot undo a newer edit.

Shutdown stops local execution even if the hub is unavailable. It preserves unsettled work and pending index delivery for recovery, closes local services and releases the daemon home lock. Process-cleanup failures remain errors. Restart reconstructs local history without launching a second step or opening a member-side hub database.
