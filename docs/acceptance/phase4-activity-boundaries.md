# Outside activity at file-changing boundaries

**Live:** local Git, HTTP, SQLite, Basic Memory in disposable homes and owned runtime child processes. **Simulated:** model responses and native-agent journals. No live outside agent or second machine is claimed. This extends the [presence checkpoint](phase4-presence.md); phase 4 remains in progress.

Context-file changes now check external activity after obtaining checkout authority and immediately before file mutations and checkpointing. Activity present at admission leaves the files untouched and permits Retry after it goes quiet. Activity detected after context application leaves the files in place, preserves checkout ownership and records a durable requirement to review the full uncommitted diff. Ordinary Retry and manual conversation actions cannot bypass that requirement. Settings → Projects → Context exposes Review changes, Refresh changes and Continue. The acceptance binds the operation, generation, project settings, canonical checkout path, Git boundary and exact file contents; a changed review is rejected. Its prepared checkpoint is durable, and restart can recover a successful Git update whose result was lost without applying or committing the files twice. A work closed with kept changes can reopen for that explicit review; Finished outside Jevellan remains a final outcome.

Queued memory checks activity at admission, before provider mutations and before checkpointing. Newly observed activity is latched while the queue runs. A partially written note stays on disk, and the work cannot silently checkpoint it together with outside edits after the journal goes quiet. Existing Changes review accepts the inspected files, then idempotent note lookup finishes the queued receipt without duplicating the note. Runtime memory mutations and index synchronization use the same fresh ownership/activity boundary.

Undo and discard now await activity checks before the actual reset/revert and again after coordination or recovery-ref waits. Published undo also checks before publication. A blocked operation preserves its checkpoint and can use its existing explicit retry flow after activity becomes quiet. Git's reviewed-checkpoint operations recheck file contents after asynchronous resource checks before changing main.

Projects with external Git policy use the same durable Changes-review barrier after overlapping activity. Their Continue action records an acknowledgement, preserving the working changes without a Jevellan checkpoint, reset or push. Deferred memory remains subject to its own ownership and activity checks. The Changes panel labels that distinction. Restart preserves an unresolved acknowledgement. A fresh writing step still requires the outside session to be quiet. Main-policy writing also checks for uncommitted files immediately before launch, so a quiet journal cannot allow outside edits from an earlier blocked launch to enter a later step. Integration retains its explicit conflict-working-tree exception.
