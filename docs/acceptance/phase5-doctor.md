# Phase 5 — Installation diagnostics

Status: implemented; the affected regression matrix and actual packed-command verification passed. The later combined installation and first-run journey is recorded in [J9](J9.md).

`jevellan doctor` prints one line each for Node, Git, APM, Basic Memory, Claude, Codex, the daemon, the hub, accounts and Jev. Missing or unavailable checks are not passes; any non-OK result makes the command exit nonzero. Version checks run with a disposable HOME, private runtime/configuration paths and no inherited provider credentials. The command does not install tools, create a Jevellan data home on a fresh machine or open native agent authentication. Installed APM and Basic Memory are checked against the selected application's recorded toolchain. Git uses the same capability check as installation.

The running daemon writes a private `doctor-control-v1` document at `doctor.json`, containing a loopback origin and a random token. Only the loopback listener accepts the token-authorized diagnostics request; browser-origin requests and the Tailscale listener refuse it. This endpoint supplies only versioned, sanitized status summaries. The daemon rotates its token at startup and removes its own control file at shutdown. Diagnostics hold lifecycle admission while running. The CLI never opens another Application or the hub database to perform these checks.

Hub checks use the existing authenticated member request, or the local authoritative hub's roster. Accounts report the last recorded readiness on this device, with a warning when the observation is older than five minutes or the last check reported an error. This does not claim a new login probe. Jev is checked through the configured model-list endpoint only when its key is saved, with a bounded request; the configured model must be listed for an OK result. Credential values, account identities and native session identifiers are excluded from the output.
