# The Projects loop

The coordinator receives owner messages and durable project events. It answers readable questions in chat, routes follow-ups to existing threads and creates tasks for new work. Propose mode keeps owner-request tasks as drafts until approved. The Overview brings numbered questions, proposed tasks, running work and pull requests together.

Concurrent refresh/event triggers share one in-flight task sweep, and shutdown drains it before closing services. The queue dispatcher applies task dependencies, ordering, Now, goal states, concurrency, daily start caps and device guards before dispatch. Jev chooses bounded placement and eligible accounts. Every thread uses a worktree outside the registered checkout. Admission enforces a shared hub limit across all projects and devices, including starts still being dispatched. The Mini remains apps-only.

Threads use the project instruction snapshot and supported native setup, shared memory and fresh Project now state. Reports return progress, tests, changed files, questions and owner commands. Usage limits retain the pending turn and retry account admission. Long waits and repeated failures can ask Jev to choose another model or effort within owner constraints. No heuristic routing chooses meaning.

A done report enters managed publication. New threads rebase onto current main, run path-selected landing checks and the smoke check, and ask Jev to choose land, detached verification or an owner decision. Publication is serialized under the hub lease. A moved main reruns preparation and checks; failed checks return an exact repair message with a three-attempt limit. Squash is usual, while configured paths and required job gates preserve merge commits. Agents do not publish main themselves.

Pull-request threads already in flight keep their delivery and saved automatic-merge policy. Their checks, conflicts and review comments can return to the same thread in bounded repair rounds. Land instead is an explicit owner conversion. Changed heads, pending owner messages and required verification retain their existing fences.

Goals refill useful tasks subject to autonomy, dependencies and caps. Nights run enabled items in order after the memory dream: command jobs before the review. Weekday selections restrict weekly work. Each command is pinned to main when it starts, placed on an eligible tagged device and admitted against project/device resources. The nightly window has a seven-hour ceiling. Missing prerequisites, failed parts and an expired window retain truthful results and produce findings; deploying remains a separate approved action.

An approved deploy pins the message revision and commit. Admission captures the before-health baseline, then durable monitoring checks at one and five minutes and repeats failures after thirty seconds. A newly broken check requests rollback, except for the database-change owner decision. Unknown completion remains unknown. Desktop work starts after health passes, with missing signing credentials disclosed up front. A rollback retains and reopens the work rather than resolving it as healthy.

Jobs may emit a versioned data outbox for ordinary tasks. Only dev artifacts enter Library; private gate inputs remain in isolated caches. The daemon creates base-only continuation branches and binds a fixed trusted gate through the originating task, including restarts. Actual landed indexes establish cache receipts. A job restart can import the outbox without rerunning its command. Retired workflow receipts remain readable; no workflow dispatch or watch chain executes.

At idle, the coordinator writes an accounted handoff before the nightly or context reset. Every owner message must be represented. The next session receives the full latest handoff, Waiting items, live work and deploy message, memory and transcript paths. Native coordinator compaction is a separate last resort at ninety-five percent. Installation-control messages retain owner identity and their optional source label. Quiet hours hold ordinary notifications durably and flush one project summary; urgent production questions bypass the hold.

Hub memory is shared across providers/devices. Turn capture supplies redacted transcript ranges; extraction produces inbox notes, recall shares them the same day, and the nightly dream consolidates durable knowledge against the code. Owner notes stay protected. Repo/device memory modes retain their existing behavior. The notebook holds plans; the rebuildable journal holds execution history.

Library files are hub-owned and hash-checked into read-only member mirrors. Variables, vault secrets and confined untracked files are supplied only to execution scopes. Scoped rigging, owner terminals, image viewing and push notifications support the owner's phone workflow without changing native homes or logins.

Paused and archived projects start nothing new; running turns finish and owner operations/polling continue. Resume immediately sweeps queued work. Resolve retains branches and worktrees, withdraws questions and supports Reopen. Full settings and UI details are in [Projects](projects.md).

The [current run log](acceptance/without-github-2026-10/README.md) records verification and installed state. [Loop history](acceptance/loop-history.md) preserves the previous file byte for byte, with all checkpoints and decisions in their original order. Historical delivery and owner-acceptance claims are not inferred from this current-state reference.

Completed jobs record successful cleanup after their owned processes, worktrees and private refs are settled. Later sweeps retain the receipts without repeating historical Git cleanup; interrupted cleanup is retried.
