Como chegámos aqui

Vento de feição, mesmo no rumo.

Vento de feição é o que sopra exatamente para onde já ia. Estávamos a meio da costa, à procura da passagem, quando o Jev apareceu.

Antes do Jev

Construímos o navio.

Chamava-se Garrison: um orquestrador para Claude Code e Codex. Já corria o trabalho em stretches curtos com handoffs, mantinha um ledger, distribuía o trabalho por contas de vários fornecedores e juntava várias máquinas numa só mesh. Os stretches curtos e focados já davam melhor trabalho com menos tokens do que uma sessão longa.

Cada enseada, um beco sem saída

O difícil era o momento entre passos.

Que fazer a seguir? Que modelo? Quanto esforço? Escrevemos duties, levels, tabelas de routing e flows, mais uma chamada ao Haiku para os casos ambíguos. O livro de regras não parava de crescer. As decisões não ficavam muito melhores.

Depois apareceu o Jev.

A TypeSafe lançou um modelo feito exatamente para esse momento: decisões rápidas e tipadas, com probabilidades honestas. Encaixou na lacuna que tínhamos deixado, como se o encaixe tivesse sido talhado para ele. A sorte não costuma vir com API.

Porquê o Jevellan

Mais do que um router.

Um router escolhe um modelo para a sua próxima mensagem. O Jevellan faz o trabalho inteiro, e traz o navio com ele.

Um berth é um pequeno pacote que traz um agente a bordo, através de um só contrato. Claude Code e Codex são os primeiros a bordo, com todos os modelos que oferecem. Gemini CLI, OpenCode e Pi vêm a seguir, e qualquer pessoa pode escrever um.

O manifest

Toda a sua configuração, num só ficheiro.

# an example manifest (apm.yml)
name: my-fleet
dependencies:
  apm:
    - my-org/team-conventions   # a skill
    - my-org/figma-export       # an MCP server
x-jevellan:
  runtimes: { claude: on, codex: on }
  menu: [Fable, Opus, GPT via Codex]
  routingProfile: |
    UI work goes to Fable.
ExportarImportar: validar, diff, aplicarapm install · apm uninstall

Agentes, modelos, rigging e regras de encaminhamento vivem num só manifest do APM, o gestor de pacotes da Microsoft para contexto de agentes. Passe-o a um amigo: ao importar vê um diff antes de qualquer alteração, e cada pacote instala-se e desinstala-se sem deixar rasto.

A rendição do quarto

Em cada handoff, o Jev é consultado.

Quando um stretch passa o quarto, o Jevellan expõe os factos e faz ao Jev meia dúzia de perguntas tipadas. O código trata de tudo o que tem a ver com recursos e limites.

Jevdecide o sentido.

  • O próximo passo, entre as ações que o código permite agora.
  • O modelo, lendo a descrição de uma linha que escreveu para cada um.
  • O esforço, em separado, porque o mesmo modelo serve para trabalho fácil e difícil.
  • A memória que vale a pena levar para este passo.

Códigodecide os recursos.

  • Que conta paga: com sessão iniciada, abaixo do limite, autorizada a gastar.
  • Guardas: limites de passos, falta de progresso, testes a falhar repetidamente, um teto de custo.
  • Git: checkpoints, a sua própria corrida de testes, e só publica quando passa.
  • Onde corre: na máquina onde começou, no checkout exato que configurou.
O Jev nunca compara números.O código transforma-os primeiro em factos: “alteração grande”, não “14 ficheiros”.

O código de sinais

Cada passo iça uma bandeira.

Os significados em itálico são os reais do Código Internacional de Sinais, aqui traduzidos. Confirmámos. Alguns encaixam bem demais.

Em 1519, Fernão de Magalhães, navegador português ao serviço da coroa espanhola, mantinha cinco navios juntos à noite com uma luz acesa na nau capitânia, o farol, e alguns sinais de lanterna. Duas luzes queriam dizer mudar de bordo. Três, encurtar vela. Cada navio respondia da mesma forma. O Jevellan faz o mesmo pelos seus agentes, com bandeiras.

replyK · KILO

“Desejo comunicar consigo.”

Responder-lhe. Sem alterações.

planP · PAPA

“No porto: todas as pessoas devem regressar a bordo, pois o navio vai largar.”

Traçar a rota antes de mexer em alguma coisa.

implementI · INDIA

“Estou a guinar para bombordo.”

Fazer ou corrigir a alteração.

testT · TANGO

“Mantenha-se afastado de mim.”

Correr os testes e acrescentar os que faltam.

reviewR · ROMEO

Sem significado isolado.

Uma revisão independente da alteração. O “LGTM” também não tem.

adversarial reviewU · UNIFORM

“Está a dirigir-se para um perigo.”

Tentar a sério partir a alteração antes de a dar por concluída.

Perguntas da tripulação

Outras dúvidas, pergunte no GitHub.

Preciso de uma chave do Jev?

Para o Jevellan se conduzir sozinho, sim. Sem ela, escolhe cada passo você mesmo (bandeira G: “Preciso de piloto”). Não há livro de regras para o substituir. Atirámo-lo borda fora.

Vai mexer no meu ~/.claude ou ~/.codex?

Não. O Jevellan tem as suas próprias pastas em ~/.jevellan, uma por conta. As suas definições, sessões e memória ficam exatamente como estão.

Pode fazer push para a minha main?

Só o Jevellan publica, só quando o trabalho está concluído, só depois de os seus próprios testes passarem no commit final, e nunca com --force. Os agentes não fazem push.

Posso usar a minha subscrição do Claude?

O Jevellan usa as contas que lhe der. Os termos da Anthropic restringem as ferramentas de terceiros de oferecer inícios de sessão com subscrições Claude sem a sua aprovação. O Jevellan não tem essa aprovação, por isso usar o seu próprio token de subscrição é uma decisão sua. As chaves de API funcionam sempre.

E se eu discordar do Jev?

Altere qualquer passo depois: corrigir e desfazer, ou só corrigir. Nunca para para perguntar antes, e as suas correções moldam as decisões seguintes.

Com que agentes e modelos funciona?

Claude Code e Codex primeiro, com todos os modelos que oferecem. Gemini CLI, OpenCode, Pi e outros vêm a seguir, cada um através de um berth. Qualquer pessoa pode escrever um berth: um só contrato, e um kit de testes que diz quando funciona.

Porquê o nome?

Jev mais Magellan, o nome inglês de Magalhães. O próprio nome Jev será uma piscadela de olho ao paradoxo de Jevons. Fernão de Magalhães foi um navegador português que deu a volta ao mundo ao serviço de Espanha. O Jevellan também é português, e navega por todos.

Está pronto?

Está na v0.1, acabado de lançar. Conte com mar agitado. Issues e pull requests são muito bem-vindos.
